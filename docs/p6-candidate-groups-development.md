## 输出与确定性分组

根字段只有 `schema_version`、`image_usable`、`target_visible`、`observations`。每个提案必须且只能出现一次，观察字段为：

| 字段 | 含义 |
|---|---|
| `proposal_id` | 原提案标识，不新增或替换对象。 |
| `entity_kind` | `physical_object` / `vehicle` / `shadow` / `surface_change` / `unknown`。前者允许可见非车辆实体群。 |
| `target_relation` | `intersects` / `outside` / `uncertain` / `unknown`；相交须依据可见实体本身与所选实际路面的关系，不能仅用提案框或支持域相交代替。 |
| `localization_status` | `single_entity` / `entity_group` / `unresolved` / `not_applicable`；区分单件、群组和边界未分离，不承担是否存在候选的判定。 |
| `entity_evidence` / `relation_evidence` | 简短中文可见依据；无法判断时说明原因。 |
| `decision_uncertainty` | 会改变实体存在或目标关系判断的未决问题；为空才允许形成确定的开发分组。性质未知、关系未知 / 不确定或图像不可用时必须非空。 |
| `description_uncertainty` | 材质细分类、单件数量、各碎片端点等描述层面的限制；本身不否定已声明可见的实体与目标相交关系。 |

不要求模型改写坐标。原框只作为待复核窗口，`instance_bbox` 固定为空；`single_entity` 也不把原框提升为精确实例标注。边界未分离可保持 `unresolved`，但若无法确定实体是否真的进入道路，必须把关系写为不确定，不能仅把这一问题放入描述字段。

确定性分组：图片或目标不可确认、实体性质未知、关系不确定或决策不确定性非空 → `needs_review`；无上述问题的阴影 / 表面变化 → `non_entity`；明确位于目标外 → `outside_target`；可见非车辆实体且与目标相交 → `candidate`。单件、实体群、材质未知均不额外阻断最后一项。车辆与目标相交始终 `needs_review`：静态出现不足以证明障碍，即使模型没有写不确定性原因也不会自动晋级。

继续整条回答原子验收。本轮不引入部分条目挽救：重复 JSON 键、重复 / 缺少 ID、未知字段、非法枚举、不完整回答或来源不一致均拒绝，全部原提案保留。无整图正常分支，`scene_verdict` 永远为空；所有人工结论为空。旧 v8 回答不能补字段或重算成 v9。
