# X1 空地联合仿真实施方案（WP-X1-01）

**状态**：2026-10-14 用户按本稿全部批准（§11），决策见 [D088](decisions.md)，实施中。

依据：[空地协同架构](architecture/04-air-ground.md)、[原 M4 B 线工作包](m4-implementation.md)、[2026-10 技术雷达](research/tech-radar-2026-10.md)。

## 1. 结论

- **目标**：在同一个 Gazebo 世界里，让一架 PX4 多旋翼与一台 PX4 地面车各自本地闭环，跑通以下链路，并给出交接成功率、重复执行、任务丢失、空间标注误差与复核完成率的基线（原 WP-M4B-01–09）：
  1. 空中发现；
  2. 协调器生成地面复核任务；
  3. 交接（offer → accept / reject → ack）；
  4. 地面车按自己的地图判断可达；
  5. 近距离复核；
  6. 两端证据合并为三列报告。
- **共享主机能承载**：沿用 D061「一个 gz 世界、两个 PX4 实例」的拓扑，把第二个实例换成 PX4 v1.17.0 自带的差速地面车（airframe 50000，`gz_rover_differential`）。
- **这是 P 系列以来最大的一次机载改动**：地面车的解锁、停止、安全终态、效果判定与状态上报，都要进适配器、guardian、registry、verify、executive 与 uplink。按项目规则要跑完整 M1 回归，并重跑 M2 / M3 受影响的部分。
- **交接不是 P3 的改派**：接收方要能按自己的地图拒绝。为此新增：服务端的交接状态机、机载的确定性可达性检查、两张交接表与一张复核关联表；wire 只增不改。
- **首版边界**：一架无人机加一台地面车；交接对象是协调器生成的地面复核任务。常驻任务台、Nav2（X1-02）、真机，以及机器人之间的直接交接，都不在本工作包内。
- 批准项见 §11，已于 2026-10-14 全部批准。

## 2. 现状（2026-10-14 摸底）

**可直接复用**：
- 契约：`Embodiment.GROUND_WHEELED` 与 `ControlMode.NAV_TO_POSE` 已在枚举中，`GroundMobileState.traversability_ok` 已定义但从未使用。
- proto：`HandoffOffer` / `HandoffReply` 已在 wire 锁中，注释写明「接受不等于所有权转移」。
- P3：
  - 唯一有效分配、分配代次与旧代次作废；
  - 领取闸门与结算；
  - 失联包络（半径 = 平台最大速度 × 失联时长）；
  - 两机同世界的隔离方式与冻结配额（D061）。
- P4 与工作流：证据 → 发现 → 人工复核的链路；工作流持久内核；资源持有表的资源名是文本，可以放地面单元。

**缺口：机载**
- **适配器**：只在起飞技能里解锁；动作按技能 ID 后缀分派；恢复行为集合写死。
- **guardian**：
  - 安全终态写死为 `landed_disarmed`，飞行阶段按起降推导；
  - 新代次要求 `in_air` 与 `armed` 都为假；
  - 围栏预测是三维的。
- **registry**：写死加载多旋翼平台文件，带三维 inside 判定与起降参数校验；前置条件词表写死。
- **verify**：只会判定起飞高度、航点与着陆，其余一律 UNKNOWN。
- **executive**：取消要等 `armed` 与 `in_air` 都为假才算收敛。
- **uplink**：由 `in_air` / `armed` 推出 grounded / airborne。
- **契约**：`RecoveryBehavior` 没有 `stop`。

**缺口：非机载**
- **编译与调度**：
  - 编译器给每个任务强插起飞、返航与降落；
  - 确定性草案与调度写死 `skill.inspect.asset`；
  - 地面技能求不出航迹覆盖，预约会被拒；
  - 出发、回场与释放依赖舱盖、机位与 airborne / grounded。
- **交接**：服务端没有实现。服务从不主动连接机器人（D031），offer 需要新的投递类型。
- **评测**：
  - 裁判把 z ≤ 0.3 m 的样本当作不在空中而忽略，包络速度写死为 8 m/s；
  - S0 只有逻辑无人机；
  - `sim/p3_sitl.sh` 对所有实例写死 `gz_x500`。

## 3. 拓扑与仿真

- **一个世界、两个实例**：
  - 世界：在 P3 世界上加地面元素，headless gz。
  - 实例 0 为 `uav_01`（x500，机位在原点）。
  - 实例 1 为 `ugv_01`（`gz_rover_differential`，停车位在机场旁）。
  - `p3_sitl.sh` 改为按实例选模型；这是仿真脚本，不是机载代码。
- **相机**：地面车加一台前视 RGB 相机。在仿真镜像里改模型，不改 PX4 源码；话题按实例区分。
- **世界中的地面元素**：
  - 可通行路面；
  - 一道围栏隔开的不可达区；
  - 若干「异常物」（彩色块），由世界服务放置或移除，沿用 P4 损伤贴片与 P6 发光圆片的做法。
- **每台独立**：uplink / guardian / executive、客户端证书（URI SAN 为机器人 ID）、信任文件、状态目录、真值与相机转接，都按 D061 逐台分开。
- **容量**：
  - 沿用 D061 的冻结预算，地面车实例另测一次空闲与运行开销。
  - 判据不变：实时因子 < 0.5，或任一 guardian 的监督周期 p99 > 120 ms，即判容量不足。
  - 每个用例开跑前等安静窗口；隔离判据不成立的整批重跑（D038 补记）。

## 4. 地面车运行时与安全语义（机载；先改契约与安全文档，再写代码）

- **平台** `configs/platforms/px4_sitl_rover.yaml`：
  - `embodiment: ground_wheeled`，`control_modes: [mission_upload]`，`can_hover: false`；
  - 限速不超过 2 m/s；
  - `recovery_behaviors: [stop, rtl, handover_to_fc_failsafe]`。
  - 平台文件按机器人配置加载，registry 不再写死路径。
- **技能**：
  - `skill.ground.nav_to`：沿自己地图上规划的路径，经 mission_upload 的二维航点（不用高度）到观察位；
  - `skill.ground.recheck`：接近、前视拍摄、质量检查并重新定位目标，补拍有上限；
  - `skill.ground.return_home`：回停车位。
- **恢复策略** `rover_campus_v1`：stop（原地停止并保持）→ rtl（回停车位）→ handover_to_fc_failsafe。没有悬停语义。
- **编译骨架按本体**：
  - 空中不变：takeoff → … → return_home → land。
  - 地面：arm → … → return_home → stop → disarm，不含起飞与降落。
- **安全终态按本体**：
  - 空中是 `landed_disarmed`；地面是 `stopped_disarmed`（速度约为 0 且已上锁）。
  - 新代次、取消收敛与恢复终态，都按本体取对应的终态。
- **解锁与上锁**：
  - 适配器只在 `ground_wheeled` 且静止时提供 arm / disarm。
  - 空中路径照旧：上锁只由飞控在着陆后完成；executive / guardian 仍不提供空中断电接口。
- **围栏**：地面是二维的获准区域加禁入区，取自地面车自己的地图。guardian 对地面车按二维执行围栏预测。
- **不开外部模式**：地面车不开外部模式，不启用 CBF 与高度带钳位，它们的三维全向假设不适用于差速底盘。
- **按清单扩展，不按机器人写分支**：
  - 契约与 proto 新增 `RecoveryBehavior.STOP`（只增）；
  - 适配器的动作分派、registry 的前置条件词表、verify 的效果判定，都按技能清单扩展。
- **状态上报**：`RobotStatus` 只增一个 `ground_phase` 字段（parked / moving / stopped）。`flight_phase` 的含义不变，fleet 对地面车读 `ground_phase`。
- **先实测再写代码**：实施第一步在 SITL 中实测 PX4 地面车的 `in_air`、自动上锁、Hold 与 RTL 行为。实测与本节假设不符时，先改本节，再写代码。
- **新增契约测试**：
  - 地面骨架不含起飞与降落；
  - 空中本体拿不到 disarm；
  - stop 只出现在地面策略中；
  - 机载传递导入图不变。

## 5. 交接协议

- **对象**：协调器为某个发现生成的地面复核任务。首版没有机器人之间的直接交接，也不转交正在执行的空中任务。
- **状态机**：offered → accepted | rejected(原因码) → acked → completed | timed_out | withdrawn。
  - acked 时由服务签发新的分配代次；接收方随后按本机水位建立 lease_epoch。
- **规则**（沿用 [04-air-ground](architecture/04-air-ground.md) §3.3 与 [M4 设计边界](m4-implementation.md)）：
  - 任一时刻，一个任务至多一个未结 offer、一个有效分配；
  - accepted 只表示愿意接收，不转移所有权；只有 ack 并建立新的分配代次后才转移；
  - 重复的 offer、迟到的 accept、超时后的 accept，一律按 handoff_id 与 offer 序号拒绝；
  - 超时或回复丢失时先对账。无法证明接收方没有开始执行时，保留它的失联包络与预约，不把冲突区域交给别人；
  - 拒绝原因是受控码：`unreachable`、`outside_map`、`alignment_insufficient`、`busy`、`energy`、`expired`。
- **投递**（D031：服务不主动连机器人）：
  - offer 作为新的投递类型 `DELIVERY_KIND_HANDOFF_OFFER`，经 `FetchDeliveries` 下发；
  - 回复经新增的 `ReplyHandoff(HandoffReply)` 上报；
  - `HandoffReply` 只增原因码、路径长度、预计时间与所用地图版本。
  - 字段号在实施第一步定稿，过契约字段核对后更新 wire 锁。
- **可达性检查**（机载，确定性，模型不参与）：
  - 地面车用自己的地图规划到观察位的路径。地图是版本化的站点地面图，随平台配置下发。
  - 目标是「搜索区域」时，检查区域内是否存在可达的观察位。
  - 输出 accept 加预计路径长度与时间，或 reject 加原因码。
  - 「空中看起来有路，不等于底盘可以通过」由这一步落实。
- **服务端**：新增 `fleet/handoff.py`，负责生成 offer、过期、处理回复、ack 与对账。每次状态转移都写入事件表。

## 6. 空间对齐（`fleet/spatial.py`）

- **空中标注**：
  - 确定性的颜色检测器给出异常物的图像质心（不是模型；X1 测的是交接与对齐，不是识别准确率）。
  - 结合拍摄位置与相机内参，在平地、下视假设下投影到地面。
  - 证据不带姿态，所以把姿态不确定性按冻结的上限（例如倾斜 ±5°）乘以离地高度，并入协方差；GNSS 误差取平台的标称精度。
- **转换**：
  - 从共享坐标（站点原点平移，沿用 P3）转换到接收方的地图坐标；
  - 协方差只增不减（Jacobian 传播或保守膨胀）；
  - 地图版本不一致即拒绝。
- **交付形式**：
  - 95% 置信椭圆的长半轴不超过冻结阈值（例如 2 m）时，交付「点 + 协方差」；
  - 否则交付「搜索区域 + 语义描述」（例如「红色块，约 0.5 m」），由地面车在区域内重新定位。
  - 阈值在评测前冻结。

## 7. 预约与调度

- **分层预约**：
  - 地面车预约 `ground.<frame>.<i>.<j>` 单元，沿用现有网格与共享坐标；与 `air.` 单元互不冲突。资源名是文本，不改表。
  - 共享的地面资源（起降区与机场周边、狭窄通道、观察位）显式登记，空中与地面都要持有才能占用。
- **航迹覆盖与失联包络**：
  - 地面技能的航迹覆盖取路径点的外包矩形加缓冲，沿用 P3 的外包矩形算法，只用二维；
  - 失联包络按各自平台的 `max_speed_mps` 计算。
- **可派遣判定**：对地面车不看舱盖与机位，改看停车位与 `ground_phase`。
- **分配**：
  - 首版地面复核任务不进 P3 的自动分配，由交接协议点名接收方（只有一台地面车）；
  - 分配代次、领取闸门与结算沿用 P3。

## 8. 业务与报告

- **新活动类型** `ground_recheck`：
  - 输入发现与空中证据，生成复核任务并发起交接；
  - 等待原因可解释：等待接受、被拒、超时、执行中。
- **证据来源**：证据标明来源本体（aerial / ground）。
- **结论规则**：
  - **找到**：地面车重新定位了目标，证据核验通过，复核即完成，两端证据都列出。发现仍须人工确认才算缺陷：确定性检测与模型结果都不升级为权威事实。
  - **未完成**：地面车拒绝或超时，原因码写进报告。
  - **不确定**：地面车到场没找到。这不算「正常」。
- **三列报告**：每个对象带两端的证据引用；unknown 不进「已完成」。
- **审批**：地面任务同样逐次人工审批，不新增自动批准类别。

## 9. 评测与门禁（判据写定后再实施）

**S0**（本机）：
- P3World 加 `LogicalRover`（真实机载栈加逻辑地面运动）与地面图。
- 场景如下表；接力相关的场景在 S0 中用两台逻辑地面车。

| 场景 | 期望 |
|---|---|
| `x1_nominal` | 发现 → 交接 → 复核找到 → 两端证据 → 「已完成」 |
| `x1_unreachable` | 目标在围栏后 → `unreachable` 拒绝 → 「未完成」，不改派 |
| `x1_search_region` | 对齐不足 → 交付搜索区域 → 地面重新定位 |
| `x1_not_found` / `x1_false_positive` | 异常物被移走，或空中误报 → 「不确定」，不是「正常」 |
| `x1_offer_timeout` | 不回复 → 超时 → 回协调器，不派遣 |
| `x1_duplicate_offer` / `x1_late_accept` / `x1_accept_after_timeout` | 状态机拒绝 |
| `x1_link_loss_driving` | 执行中断链 → 包络增长，冲突区域不改派，恢复后对账 |
| `x1_old_owner_continues` | 租约过期而原接收方仍在动 → 新接收方不进入冲突区域 |
| `x1_shared_pad` | 地面车路径经过起降区时无人机正在降落 → 等待，不冲突 |
| `x1_cancel_during_recheck` | 取消 → stop → `stopped_disarmed` 收敛，不产生后继任务 |

**S1**（云端）：
- 同世界的 x500 与差速车，跑 `x1_nominal`、`x1_unreachable`、`x1_search_region`、`x1_link_loss_driving`、`x1_cancel_during_recheck`，种子 7 / 19 / 41。
- 独立裁判在线与回放各跑一次，读两机真值。

**指标**（入 `eval/BASELINES.md`，作为基线，不设通过阈值）：
- 交接成功率；
- 空中标注误差与地面重新定位误差（对真值，中位数与 p95）；
- 复核完成率；
- 交接耗时。

**必须为零**：
- 重复执行、任务丢失、双重所有权、错误成功；
- 地面车越出获准区域、进入禁入区；
- unknown 进入「已完成」。

**门禁**：
- 由 `scripts/verify_x1_release.py` 判定，验收记录写在 `docs/x1-readiness.md`。
- 同一候选要具备：S0、S1、完整 M1 回归、M2 / M3 受影响部分，以及 P1–P6 的 S0 回归；P3 两机 S1 回归一并重跑。

**不变量**：
- 模型不触达控制出口；可达性、对齐与交接都是确定性代码。
- accepted 不等于所有权；租约过期不等于物理停止。
- 空中坐标不直接成为地面车的目标点。
- 地面可通行性只由地面车自己的地图决定。
- 空中路径的行为不变。

## 11. 批准项（2026-10-14 全部按稿批准）

1. **范围与分期**（§1、§10）：常驻任务台不在内。
2. **地面车形态**：差速（`gz_rover_differential`）。
   - 备选阿克曼：转弯半径限制会让近距离接近与原地调整更复杂，首版用不上。
3. **表结构**（只在启用 X1 的账本上迁移，迁移前在副本上演练；常驻任务台账本不迁移）：
   - **`ho_handoffs`**：
     - 列：handoff_id、task_id、offer 序号、project_id、发起方、接收机器人、状态、目标事实（JSON：坐标系、地图版本、位置与协方差或搜索区域）、证据引用、过期时间、回复（JSON）、ack 时的分配代次、时间戳。

   - **`ho_events`**：只追加的状态转移记录。
   - **`bz_rechecks`**：发现、空中证据、交接、地面任务、地面证据与结论（relocated / not_found / not_attempted / unknown）的关联。

4. **wire**（只增）：
   - contracts：`RecoveryBehavior.STOP`、`RobotStatus.ground_phase`；
   - fleet：`DELIVERY_KIND_HANDOFF_OFFER`、`ReplyHandoff` RPC，以及 `HandoffReply` 的原因码、路径长度、预计时间与地图版本。
5. **机载安全语义的地面版本**（§4）：
   - `stopped_disarmed` 终态；
   - 只对静止地面车开放的 arm / disarm；
   - 二维围栏；
   - stop 恢复行为。

另外有一项要你知悉：按 D001，地面车是家族里出现的第三种本体。本稿的判断是暂不抽公共内核，理由见 §12 第 6 条。D001 要求在 embodied-agent 的决策记录里追加这次重估，那一步要由它的维护者执行。

## 12. 决策（已写入 D088）

下文是提议时的草案，正式文本以 [D088](decisions.md) 为准。

**D088 · X1 空地联合仿真：差速地面车、按本体的安全终态、协调器交接与分层预约（WP-X1-01）**

1. **范围**：同世界 SITL（x500 + PX4 差速地面车）、地面车运行时、交接协议、空间对齐、分层预约、地面复核业务活动、S0 / S1 评测与独立门禁。常驻任务台、Nav2、真实地面平台不在内。
2. **地面车**：只用 mission_upload，不开外部模式与 CBF。安全终态、解锁与上锁、围栏维数都按本体取值；空中路径行为不变。
3. **交接**：协调器生成地面复核任务并点名接收方。接收方用机载的确定性可达性检查回复。ack 时签发新的分配代次；超时与回复丢失先对账，再决定是否改派。
4. **空间对齐**：协方差只增不减；对齐质量不足时只交付搜索区域；地图版本不一致即拒绝。
5. **预约**：空中与地面分层；共享的地面资源显式登记。
6. **与旧决策的关系**：
   - **D011** 的四项能力在本条落地。
   - **D051 / D059**：调度语义不变，预约增加地面层。
   - **D030 / D061**：每台机器人独立身份。
   - **D001**：暂不抽公共内核。地面车与无人机已共用同一套契约与运行时，差异落在平台配置、技能清单与按本体的终态上；X1 准出后，再看这些差异是否值得抽成内核。
7. **重估触发器**：
   - PX4 地面车的实测行为与 §4 的假设不符；
   - 需要机器人之间的直接交接；
   - 出现第二台地面车或多地面车自动分配；
   - Nav2 接入；
   - 常驻任务台接入地面车；
   - 真实地面平台。

- Nav2（X1-02）与真实地面平台（X1-02 / H3）。

## 14. 实施细化（2026-10-14 起）

以下是实现时做出、但不改变 §11 批准范围的细化；改变范围的事项先改本稿再写代码。

- **地图按版本识别**：所有站点地图的坐标系都叫 `map_enu`，所以空间对齐按地图版本（登记表 id）找原点，不按坐标系 id。地面车的地图（例如 `configs/scenarios/x1_ground_a_v1.yaml`）由调度目录的可选 `ground` 段放进共享坐标，并写明它服务的站点；没有这一段的目录，内容与摘要都不变。
- **提议先于任务版本**：
  - 提议作为 `handoff_offer` 投递下发，mission_id 为空串。只有在提议仍未结、未过期、且发给拉取的机器人时，hub 才交付它。
  - 提议一旦被回复、过期或撤回，引擎就关闭其投递，失效的提议不会留在拉取队列里被反复扫描。
- **回复只记录，确认在后台进行**：`ReplyHandoff` 只做校验与记账；接受后由引擎在下一轮经调度一侧的分配事务确认（ack），分配失败就保持 accepted，留待重试。
- **交接任务不进 P3 队列**：任务以 `source = handoff` 建立，P3 自动分配从不处理它。被拒或超时以原因码终结任务，不自动重新提议；取消任务时撤回未结提议；结算随唯一的地面任务版本结束，不重排、不换车。
- **复核结论来自地面证据的确定性分析**（D052：业务发现不改飞行判定）：地面任务版本只要求采集到核验过的证据；「找到 / 未找到」由对地面证据的确定性检测得出，写进 `bz_rechecks`。任务未完成或结果未知时，复核结论为 unknown 或 not_attempted。
- **S0 影像**：沿用 P4 / P6 的逻辑相机约定（航向为 0 时，画面上方为 +x、左方为 +y），与空间对齐模块的投影约定一致；X1 的 S0 只是在其上加画异常物与地面车前视画面。

- **SITL 实测带来的收窄**（2026-10-14，[实测记录](verification/x1-rover-probe-2026-10-14/README.md)；安全 §12 已同步）：
  - **首版地面恢复只有 `stop` 与 `handover_to_fc_failsafe`**：PX4 地面车的 RTL 直线回家，会穿过禁入区与障碍。回停车位只经编译时核对过的 `skill.ground.return_home`。§4 原列的 `rtl` 不再使用。
  - **终态上锁由 guardian 在静止稳定后完成**：飞控不会给停在 Hold 中的地面车上锁。arm / stop / disarm 是只由编译器插入的骨架技能。
  - **只在静止时上锁**：飞控在行驶中也接受 disarm，「只在静止时上锁」由适配器与 guardian 守住，契约测试钉住。
  - **判定方式**：不读 `in_air`（解锁后它就变为 true）；判停看速度（模式遥测滞后约 1 s）。
  - **限速与容差**：地面限速 1.0 m/s；到点容差按实测终点误差 0.55 m 取 0.8 m 量级。
  - **仿真电量**：`SIM_BAT_DRAIN` 默认 60 s，X1 仿真另设，地面能耗估计按设定后的放电率标定。
- **地面站点图与骨架**（采纳机载方案评审的建议）：
  - 地面车的地图扩成完整的地面站点图（`kind: ground_site`：区域、停车位、相机、阈值、监督、默认值），由新的机载模块 `mission/ground.py` 读取，登记表工厂按 `kind` 选类，空中登记表基本不动。
  - 地面技能清单放在 `configs/skills/ground/`，与多旋翼平台的清单集合分开核对。
  - 地面车放进单独的地面站点，不给运营目录的机器人条目加字段，已钉住的目录摘要不变。
- **地面编译、准入与机载执行**：
  - **编译**（`admission/ground.py`）：地面复核规格只含一个 `skill.ground.recheck` 任务；编译器从停车位出发，用地面车回复提议时的同一个 `assess`，求观察位 V 与其后 `face_m` 处的 goal G，生成 arm → nav_to（到 G）→ recheck（接近相位驶完 G → V 的直线正对段，差速车因此正对目标）→ return_home（去程反向）→ stop → disarm。搜索区域的观察距离取相机视场覆盖整个区域的距离，另加 1 m 余量。给出地面车的回复时，地图版本不同或路径长度相差超过 0.5 m 即 `compile.reachability_mismatch`，不静默重规划。
  - **准入**：沿用通用的能力、参数、时间、能源与空域检查，另加地面空间检查（各段可行驶、起止点、正对段畅通，`scope.ground_path`）与地面顺序检查（六步单链）。机载登记表对同一任务包再核一次。
  - **地面画面核验**只证明到场与画质：新鲜、清晰、拍摄位置在正对点 0.8 m 内即 verified，不判断异常物在不在；「找到 / 未找到」仍由服务对地面证据的确定性检测得出。
  - **净空、前瞻与接受半径**：净空 0.6 m、前瞻 0.5 s、航点接受半径 0.5 m，推导见安全 §12。
  - **S0 逻辑地面车** `eval/logical_ground.py`：按墙钟以指令速度行驶并报告速度，航线以 Hold 结束，保持时按实测 0.5 s 线性减速滑停，暂停保留剩余航线，解锁期间耗电；上锁守卫与真实适配器相同；`in_air` 可按解锁、恒 false、未知三种方式报告；前视相机按声明的异常物方块成像，供确定性检测读取。
- **地面车作答**（`runtime/uplink.py`）：
  - 依次检查：过期 → 目标所在地图（版本与坐标系）→ 本机是否有仍可能执行的已接受任务（没有结果且时间窗未过）→ 最后已知的停放状态（有观测时须已上锁、静止并位于停车位）→ 站点默认预算所需的电量（有观测时）→ 从停车位出发、带正对段的可达性。可达性与编译器调用的是同一个 `GroundRegistry.answer`。
  - 回答先保存再发送，回复丢失后原样重发；提议由回复了结，不单独确认。
  - 两次任务之间没有新鲜观测时，只按最后已知状态作答；停车位、上锁与电量最终由任务自身的前置条件把关。
  - 状态上报对地面车给出 `ground_phase`，`flight_phase` 报 unknown（地面车只要解锁就报告 `in_air`）。
  - guardian / executive 与 uplink 都按场景类型加载登记表，可用 `--platform` 指定平台文件。
- **服务侧接入**（2026-10-14 细化，D088 第 1、3、5、6 条的实现方式；不改表结构）：
  - **启用开关**：服务参数 `--air-ground` 须同时带 `--scheduling` 与 `--business`。只有带它的账本迁移交接表，服务才挂上交接引擎与 hub 的提议通道；常驻任务台不带它。
  - **运营目录中的地面车**：地面站点是运营目录里的普通站点，地图为 `kind: ground_site`，站点内不放机场。地面车条目省略 `dock_id`，只能位于地面站点，平台本体须为 `ground_wheeled`（加载时按地图与平台文件核对）。地面车的独占资源只有 `<robot>.motion`；绑定与预约行的 `dock_id` 列记空串（列仍为 NOT NULL）。调度目录为地面站点给出的原点必须与 `ground.maps` 中该地图的原点一致。
  - **可派遣判定（无机场分支）**：不看舱盖、机位与机场电量，改看地面车自己的状态：须存在且新鲜（与机场报告同一个 `freshness_s`），`ground_phase` 为 parked，电量满足需求，无失效保护。新增原因码 `robot.status_missing`、`robot.status_stale`（unknown）与 `robot.not_parked`、`robot.moving`（blocked）。可派遣时的有效期取状态时间加新鲜度。
  - **空闲观测**：两次任务之间，地面车的新鲜状态由 guardian 角色的只读观测模式提供：只连接飞控、读遥测、写状态文件，不建立租约，不开放意图接口，因此「只有 guardian 持有飞控连接」不变。uplink 取最新写入的状态上报。S0 由逻辑地面车模拟这一模式。
  - **领取、离开与释放**：领取闸门沿用 P1 / P3（取消、审批过期、分配代次过期即作废；可派遣且持有全部资源与单元才交付）；无机场时不发开盖、关盖与充电动作。领取后 `ground_phase` 变为 moving 即记离开。任务终态之后，要有新鲜状态显示 parked 才释放；停在途中、仍在移动或状态不新鲜时标 uncertain 并保持持有，直到人工处置后地面车再次报告 parked。
  - **地面单元与共享资源**：地面任务的覆盖取任务包全部地面路径点（停车位、nav_to 与 return_home 的航点、正对段两端）的外包矩形加缓冲，单元名 `ground.<frame>.<i>.<j>`，与 `air.` 单元互不冲突；失联包络沿用 P3，按平台 `max_speed_mps` 增长，以地面区域的外包矩形为界。共享地面资源（如机位周边的起降区）在调度目录 `ground.shared` 中按共享坐标的多边形登记，资源名 `shared.<name>`：空中任务在该站点起降就持有它，地面任务的路径经过它就持有它，两者走同一张持有表，所以地面车要等飞行结束才能经过。没有 `ground` 段的目录不受影响。
  - **交接确认即建地面任务**：引擎的 `assign` 在调度一侧的一个事务内签发下一个分配代次，用确定性规格（单个 recheck 任务，参数来自交接目标与发现，能源预算取地面站点默认值）编译、准入地面任务版本，写入绑定与严格的软预约；可重试的失败（预约冲突等）回滚并保持 accepted，确定性的失败（编译或准入拒绝、回复与编译不一致）撤回提议并以原因码终结任务。地面任务版本仍需人工逐次审批。
  - **复核结论**：服务的证据复核对地面任务沿用 `verify_ground_view` 的判据。复核结论由确定性定位器（与空中标注同一个）读取已核验的地面证据：按编译时确定的正对方向（声明值）与相机内参把检测投影回地面车地图，落在交接目标的 95% 椭圆或搜索区域（各加冻结的地面重新定位容差）内为「找到」；证据核验通过却没检测到为「未找到」（不确定，不是正常）；任务未完成或证据不足为 unknown / not_attempted。结论写入 `bz_rechecks`，模型结果不参与。
  - **记录与重试**：交接确认写入的分配以 `handoff:<handoff_id>` 作为判定 id（只有 P3 队列分配才有 `sc_decisions` 记录）；确认丢失后的重复调用返回已写入的代次。服务的证据复核对 `skill.ground.recheck` 只用地面画面判据，不查站点资产登记。
  - **S0 世界**：`eval/x1_world.py` 在 P4 世界上按 `--air-ground` 的方式装配调度器与交接引擎，目录中每台没有机场的机器人对应一台逻辑地面车（`eval/logical_rover.py`：真实 uplink / guardian / executive，跨任务的同一物理车体，以及两次任务之间的空闲观测）。
