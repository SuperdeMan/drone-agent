**P5 未准出（2026-10-05，候选 `4c3de14`）。** 门禁二十二项中二十一项通过，只有 **soak** 未通过。72 小时真实墙钟长稳的七条判据中六条通过，未通过的是恢复判据：最后一次服务重启（10-05 15:00 UTC）后，服务 4 秒就绪，但四个机场会话 67.5 秒才全部恢复活动，超过冻结的限值（就绪后 60 秒）。
- **根因**（已在云端复现并剖析）：服务启动时在事件循环里同步刷新账本中的全部任务，三天后共 666 个。每个任务都要逐像素重算证据影像质量，并多次全表扫描 `events` 表（该表没有可按任务查询的索引）。这一轮刷新占满 0.5 CPU 配额约一分钟，同一事件循环上的 API 在此期间无法应答。耗时随任务数线性增长，9 次重启依次为 12 → 67.5 秒。
- **其余判据都成立**：72.001 小时、同一版本、账本从未重置；三个服务排班各 143/143 次，错过 0；327 个编排发生时刻都有结果；573 个运行无丢失；十三项计数全 0；资源无意外重启、无 OOM；分层最低要求全部满足。
- **其余二十一项门禁**：S0 / S3、授权矩阵、S1、P1–P4 S0 与 S1 回归、M2、任务台、一入口主场景、备份恢复、P4 依赖与历史记录都在同一候选上通过。

按 D073，阻断缺陷修复后要以新候选重新开始 72 小时；本候选的记录保留为负记录。修复方案见文末「下一步」。

计数与证据边界：
- S0（逻辑飞行）、S1（一架 PX4 SITL 飞行器与逻辑机场）、S2（VisA 校准拆分上的实调探针）与 S3（厂商协议模拟器）分开计数，互不替代。
- S3 只证明网关与本项目自定的协议档案在模拟器上的合同；档案 `verified_against_firmware: false`，不证明任何真实厂商固件或设备。

- 工单是账本中的模拟工单；长稳中的审批、复核、维修反馈与取消由编排以 `harness:soak-*` 身份完成，计为编排介入。
