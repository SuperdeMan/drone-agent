## 实施中的发现

设计最初给出 8 个索引。实施中用阶梯工具做了三轮检查，每一轮都找出了设计没看到的、随历史增长的开销；全部在候选中改正，并由计划测试逐条钉住所用索引。

| 手段 | 找出的问题 | 处理 |
|---|---|---|
| 稳态语句清单（在 1× 合成账本上，跟踪一个稳态窗口内的全部语句并取查询计划） | 每轮：待领取任务包、活动预约、活动工作流运行都扫描全表。每次任务刷新：证据、核验、事实、问题全表扫描；任务视图读出机场全部动作再在内存中筛选。启动时每个任务都刷新一次，所以启动核对随历史平方增长 | 7 个索引。活动运行改为列出仍在运行的状态；任务视图按活动键范围读动作；资源视图只取最新 20 条。`cap_deliveries_open` 只建在未确认行上、按游标排序，同时服务机器人拉取与每轮扫描 |
| 设计稳态测量时的代码核读 | 状态归档追平后，每一轮都要扫描保留窗口内约 220 万行较新的状态行（`created_at` 无索引） | 按 id 二分查找截止行，只读该范围，只归档完整的块；无事可做时休息 30 s |
| 16× 账本上的重放计时（跑一段稳态，记录全部语句后逐条重放计时） | 以下读取走索引，但读出全部历史再截取：审计列表的三个来源、任务单列表、资源视图的最新预约、业务作业（按项目、发现、运行）、工作流子运行与出站消息、机器人的活动分配 | 4 个基础索引与 6 个后置索引；审计来源按时间索引倒序取满一页即停；任务单列表分两次读取。一个新索引（`deliveries(kind, …)`）曾抢走每轮任务包扫描的计划，改为只含操作请求的部分索引 |
| 独立审查（只在主机上运行的路径） | 见下方四条 | 见下方四条 |
| 第一轮阶梯 | 归档每次调用只限制返回的状态行数，没有限制读取的行数。16× 时，第一块读穿了模板状态行与状态窗口之间的 68.7 万行其他事件（1× 为 2.7 万，4× 为 15.8 万） | 每次调用至多读 2 万个 id 的窗口，没有状态行的窗口记为已扫过；窗口在截止前结束、或该日早于截止日时，块也算完整 |
| 第二轮阶梯 | 关键的 16× 窗口有 7 分钟在电池上运行，前后的 CPU 基准看不到 | 新增本机电源记录（独立进程每 5 s 一个样本）；门禁要求每次测量全程接交流电、样本间隔不超过 30 s。第三轮的睡眠正是由它识别的 |

独立审查找出的四个问题及处理：

1. **长稳采样重复计数**：两次读取之间提交的归档块会被计两次，裁判会误判 `op_events` 下降。改为计数共用一个读快照，并且全部读到才记录。
2. **旧备份的恢复演练**：D085 之前的备份做恢复演练必然失败。改为先做容量迁移演练。
3. **就绪等待**：首次启动的迁移可能超过 120 s 的就绪等待。就绪等待改为按演练用时放宽。
4. **归档读回断行**：读回时用 `splitlines` 会在 JSON 未转义的分隔符处断开。改为只按 `\n` 分行。

另外，容量演练原本对整个账本做两次 `iterdump` 并读入内存（任务台账本上约 3 GB），改为流式摘要。

## 规模阶梯

- **合成历史**：
  - 模板：在 S0 任务台世界（任务台四个目录）中飞 9 个运行，即机队 6、厂商 2、园区 1；园区资产被判为疑似后，由复核人驳回。
  - 克隆：按实例 id 求闭包后克隆到 1× / 4× / 16×，即 1291 / 5164 / 20656 个任务、19 / 76 / 304 天跨度。克隆替换全部实例 id 并平移到时间槽，再按服务的算法重算任务包哈希、溯源封印、执行日志哈希链与事件 id、报告的溯源摘要。
  - 状态行：最后 7.5 天每天 31.4 万条机场状态行，按时间交错写入。
- **确定性**：同一模板与种子得到逐字节相同的账本，三个账本的摘要写入预登记。
- **自检**：每档让服务刷新 9 个模板任务与 300 个抽样克隆，一行都不写。
- **测量**：
  - 每档、每个变体一个独立进程，以高 QoS 运行，前后各测一次固定 CPU 基准；旁边的电源记录覆盖全程。
  - 依次测启动、启动核对、归档（只带迁移）与 10 分钟稳态窗口。
  - 稳态窗口内：机场每秒报告，每 2 分钟一个实时机队巡检，每秒一次接口探测。

## 已知限制与接手项

- **厂商网关启动**：每次启动从账本重建未结束任务时，会读出全部厂商日志（16× 时查询约 0.35 s，只在启动时一次）。只读未结束任务要改变「未结束」的判定依据，未做。
- **P2–P4 迁移演练**：三个存储的迁移演练仍把整库转储读入内存（任务台账本上各约 2–3 GB 峰值）。归档使 `op_events` 不再增长后压力已减，改为流式摘要列为接手项。
- **阶梯里的每任务核对耗时偏低**：合成历史中克隆共享模板媒体，影像质量缓存因此命中率偏高，阶梯中的每任务核对耗时比任务台真实值低。判据比较的是各档之间的比值，不受影响；任务台的绝对值见上节。
- **本机测量的脆弱性**：约 2 小时的本机测量会被断电、合盖与睡眠打断。第二、三轮都因此作废，电源记录把这类情况变成可判定的无效。
- **72 h 长稳**：不在本工作包内运行。长稳采样与裁判已按归档调整（`op_events` 加已归档行数守恒）。
