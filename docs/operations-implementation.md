## 1. 交付顺序与责任

当前最短路径：P0 来源契约与门禁 → P1 单机场纵向实现 → P1 三机场逻辑验收 → P2 单机持久业务闭环 → P3 调度与 P4 分析并行 → P5 集成长稳。P2 的契约设计和模板原型可在 P1 单机场子集完成后开始；P2 正式准出仍依赖 P1。H1 硬件到位后独立启动，不阻塞 P 线。

角色是责任类型，不代表已有人员分配：**B** 后端 / 契约，**S** 仿真 / 运行时，**F** 入口 / 交互，**V** 视觉 / 数据，**Q** 独立验证，**O** 场景与交付负责人。1–3 人可兼任；实现者可以准备证据，验收结论必须由独立裁判和可复算记录支持。

| 阶段 | 估算投入（人日） | 主要依赖 | 准出交付 |
|---|---|---|---|
| P0（已完成） | 原估 3–5 | 本次文档基线 | 来源契约、门禁消费、能力清单 |
| P1 | 18–28 | P0；持久化具体方案批准 | 3 站 / 3 虚拟 UAV、单机 SITL 接入、资源与故障证据 |
| P2（已完成） | 原估 22–35 | P1 | 可重启的巡检—分析—复核—模拟工单流程 |
| P3 | 25–40 | P2；两机仿真资源测量 | 逻辑规模与两机同世界执行、调度基线 |
| P4 | 20–35 | P2；可用且有权使用的数据 | 主场景实调分析、人工复核、复检闭环 |
| P5 | 10–18 + 72 h 观测窗口 | P3、P4 | 系统级 v0.1、第二模板、S3 合同测试、长稳报告 |

以上是按当前模块边界给出的规划估算，不是完成承诺；不以 M1–M3 的日历推进速度外推，也不把共享主机容量视为已满足 P3。H 线不在此估算中。
