# M2 评审与云端飞行台合并（2026-09-24）

## 结论与范围

M2 已形成可运行的受约束规划、编译准入、人工审批、签名投递、机载执行与证据报告闭环。历史 M2 发布门禁只属于 `f362b9e`；评审起点为 `dc48b5f`，评审开始时线上为 `74984f9`。本次发现的证据闭环缺陷需要修复，不能用历史通过数字排除它们。

M1/M2 可以合并使用入口。采用 D037：`8448/` 为自然语言任务，`8448/fixed/` 为固定巡检，共用导航、私网身份和工作区锁；保留各自后端与证据裁判，不合并机载控制出口。旧 `8447` 是兼容入口。M1 的本地可信固定包与 M2 的人工审批签名包权限不同，直接把任意 M2 请求送进 M1 代理不可接受。

## 架构评估

- 规划层：模型只返回草案；检索只读，结构化输出校验和有限重试不授予执行权限。脚本回答与 MiniMax 实调需要分别报告。
- 准入层：登记的空间、能力、时间、能耗与参数独立检查；空域桩拒绝真实模式，仍只适用于 SITL。
- 执行层：uplink、executive、guardian 分别验签，executive 无网络，guardian 是唯一飞控出口；重规划只在落地后以新代次接管。
- 服务层：账本镜像最终一致，服务停机不影响已授权飞行；本轮补齐了镜像完整性与影像迟到的状态收敛约束。
- 合并范围：网页增加既有 M1 代理 socket、只读运行与版本目录、独立证据页面缓存。没有 Docker socket、SSH 私钥、签名私钥、模型 key 或仿真网络。固定模式 POST 与 M2 一样要求已识别操作者，并继续校验 Origin / nonce。

## 当前限制与后续工作

M2 仍是单机、登记航线巡检；局部自主、真机、多机器人均未交付。M2 巡检步骤没有可暂停能力，不能因为 M1 有暂停按钮就宣称两者等价。排队但未起飞的 M2 任务撤回仍未实现，需要单独定义撤销投递与 inbox 的一致性。规划过程中服务重启的恢复、长期证据保留策略和多用户权限应在扩大常驻使用前单独设计。

本轮运行版本、部署回执、真栈结果与浏览器可用性将在完成验证后追加；新版本不继承历史 M1 66/66 或模型准入率基线。
