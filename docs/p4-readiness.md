## 已实现范围

- **质量层与分析作业**（WP-P4-02，D063）：`quality-v1` 在服务证据复核之后确定性地检查媒体摘要、分辨率、曝光、清晰度与采集时刻，只能拒判。分析作业固定输入清单、参考图与画像摘要，在服务进程内按租约领取、代次 fencing、并发上限、超时、有界尝试与按项目的每日 token 预算执行；每个作业以带来源（`live_model` / `recorded_model` / `scripted` / `deterministic`）的候选结论或带原因的拒判结束，并按 D054 追加为任务版本来源。
- **模型分析器**（D063 §4、D066）：消息只含登记参考图、当前图与固定文本，没有工具；回答必须恰为 change-v1 模式的 JSON，多余字段、类型不符或未列出的缺陷类型都是 `model.malformed`；按 τ 确定性映射。冻结的 change-v3 允许模型先推理、只解析最终 JSON，使用三张参考图。
- **候选发现、复核、工单与复检关单**（WP-P4-04/05）：疑似结果按（项目、资产范围、资产、缺陷族）聚合为唯一的未结发现；只有项目 reviewer 的首个决定生效；每个发现至多一张工单；维修反馈在同一事务中开启一轮并启动复检运行；`reinspection-v1` 按反馈之后的新采集、未见过的媒体、允许来源的未疑似分析与本轮复核结算，缺任一条件记 `failed` / `unknown`。
- **数据复用与参考外观**：operator 对本项目已复核的采集提交复用分析（`reuse-v1`：模态、分辨率、时效、分析器不符即拒），复用结果不进入结算；admin 登记 / 撤销参考外观，分析取最近 k 份有效参考。
