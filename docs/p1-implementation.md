# P1 详细方案：资源目录与虚拟机场

[总任务表](operations-implementation.md) · [运营架构](architecture/09-operations.md) · [路线图](roadmap.md)

**状态：2026-09-25 待实施。** 首个资源产品能力里程碑；P0 已在 `de597d0` 完成，来源与门禁可直接复用。目标是在现有任务服务上交付 3 个站点、3 个虚拟机场和 3 台逻辑 UAV，并让一个机场可接现有单机 PX4 SITL。虚拟机场不是 DJI 仿真器，也不代表真实机场硬件已验证。

## 1. 验收场景与范围

- `site_a/dock_a/uav_a`：正常，固定绑定 S0；先作为纵向开发对象。
- `site_b/dock_b/uav_b`：可注入充电 / 冷却与能源不足。
- `site_c/dock_c/uav_c`：可注入维护、离线、过期和舱盖卡滞。
- 单机 S1 接入使用独立运行配置，将一个站点绑定现有 `uav_01` 和 M2 预验证航线；不在运行中把某个 S0 robot ID 改成真实执行器。

首版人工选择资源或由固定绑定确定执行者，服务负责判断能否派遣。最小资源集合为 robot.motion、起降位、充电位；P1 只做独占和生命周期对账。多候选排名、跨机场异地着陆、任务接力和通道规划属于 P3。

本里程碑交付最小列表 / 详情 / 拒绝原因与审计，不引入地图编辑器、流程画布、新账号系统或厂商远程机械控制。

## 3. 数据与 API 设计边界

P1 服务对象按[运营架构 §2–3](architecture/09-operations.md)定义。版本化目录可先用配置文件；状态、预约、取消 / 派遣决定与事件必须持久化。SQL 表、索引、升级方式在 WP-P1-02 输出具体设计，未批准前不改数据库 schema。

| 拟新增服务方法 | 输入与权限 | 输出 / 不变量 |
|---|---|---|
| `resources.list` / `resources.get` | 受信 actor + project + resource ID；项目 read | 目录、状态年龄、来源与阻断原因；跨项目返回不可访问，不泄漏媒体 |
| `resources.eligibility` | project、固定设备、任务需求摘要 | eligibility、所有 reason codes、输入快照 / 策略版本和到期时间；只读，不产生授权 |
| `resources.reserve` / `resources.reconcile` | 内部服务活动身份；项目授权及稳定 activity ID | 原子独占、重复键返回原结果；不允许浏览器指定“已落地”来释放占用 |
| `docks.ingest_status` | 已绑定的后端身份、boot/seq、观测与有效期 | 拒绝错误设备、倒序与过期会话；状态来源不能由客户端自报为 real |
| `simulator.inject` | 仅隔离的测试 harness | 故障进入模拟器，不成为正式任务台 API，不挂载到真机入口 |

以上方法是待实现 API，现有 `fleet.api.METHODS` 尚不含这些名字。设计时保留现有 submit/approve/operate 调用；新项目字段使用明确版本的入口，不能让旧调用静默取得所有项目权限。旧运行数据归属只按审核后的固定 legacy project 映射，不从任意请求自动推断。

**TOCTOU 处理**：页面查询 eligible → 人工审批期间可能变为维护或离线。交付领取时按最新状态和预约再校验；旧的 eligibility 不能兑换成飞行许可。已领取交付与取消竞态留审计、走对账；未领取交付在取消后失效。P1 的实现为后续 P2 取消屏障提供复用点。

## 5. 故障与验收矩阵

| ID | 注入 / 操作 | 期望可观察结果 |
|---|---|---|
| P1-F01 | 正常设备、足够能源、有效审批 | 正常任务完成；逻辑与 SITL 结果分别计数 |
| P1-F02 | 充电中 / 冷却中 / 返程能源不足 | 新派遣被拒，原因分别保留 |
| P1-F03 | 维护锁定后迟到正常状态 | 维护锁不被遥测解开；只能授权运维操作解除 |
| P1-F04 | 机场离线 / 状态 >3 s / 来源未知 | eligibility blocked 或 unknown，无新投递 |
| P1-F05 | 未来时间 >1 s、倒序 seq、旧 boot 会话 | 拒收或未知，不延长有效期 |
| P1-F06 | 舱盖开启 ACK 到达但动作卡滞 | 不进入可起飞状态，不以 ACK 当开盖完成 |
| P1-F07 | 充电动作成功 ACK、实际未增长 / 异常 | 补能未达标，不因计时到点变 ready |
| P1-F08 | 两任务竞争同一起降位 / robot.motion | 一个持有者；另一个等待 / 拒绝，重复请求返回既有预约 |
| P1-F09 | 飞行已落地、回执丢失 | uncertain 保留；重启不释放；状态与任务证据对账后才释放 |
| P1-F10 | 机场在位与无人机 airborne 冲突 | 阻断新派遣并暴露冲突，不能任选一条正常值 |
| P1-F11 | 领取交付前变为维护 / 审批过期 / 收到取消 | 重新检查失败，无新交付领取；已领取的请求另行对账 |
| P1-F12 | 服务 / 模拟器重启、重复或迟到 ACK | 状态收敛到原任务，不创建替代飞行；未知效果不重发 |
| P1-F13 | 跨项目资源 / 任务 / 媒体访问、伪造角色 | 服务端拒绝，不泄漏数据，不签发任务包 |
| P1-F14 | 把 S0 来源改成 real、真实后端 ID 注入 | 受信绑定拒绝；测试环境无法接触真实设备和凭据 |

P1-F01 同时在 S0 与 S1 执行；其余以 S0 确定性故障为主，P1-F11/12 的服务到单机执行链至少各一组 S1 验证。资源页刷新、入口重启、固定任务操作和取消语义按受影响范围回归。所有注入记录层次，逻辑充电测试不证明物理电池模型。

## 6. 证据、门禁与接手

拟定 `docs/verification/p1-<date>/` 保存候选、控制面 / 场景哈希、来源、场景 seed、API / 资源事件、预约变化、任务包 / 审批引用、裁判及回放结果。媒体正文与大日志沿用云端 artifacts，不把敏感凭据放回执。

准出要求：P0 已关闭；3 站 / 3 逻辑设备；P1-F01–F14 × 3 seed；单机 S1 的正常与集成故障通过；重复派飞、冲突放行、错误释放、项目越权、假成功均为 0；受影响的 M1/M2 同版本回归完成。若变更执行 / guardian / 自主层，再按对应契约补同版本 M3-SITL 回归。没有触碰该路径时，不为目录页面改动重跑无关的全部实飞矩阵。

P2 接手物：资源与错误码版本、稳定项目身份、预约和取消屏障、任务服务提交 / 查询 / 对账入口、运行来源、单机场 S1 配置及完整回执。P1 完成不证明持久工作流、多机飞行、VLM 识别或机场硬件已就绪。
