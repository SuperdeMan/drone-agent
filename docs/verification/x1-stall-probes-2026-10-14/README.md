# X1 地面车停滞与限速探针（2026-10-14）

这是 S1 运行中两次「地面车进入任务模式后原地不动」之后做的诊断，只是测量，不是发布门禁，也不计入任何验收。结论写入[实施方案 §14](../../x1-implementation.md)与[安全 §12](../../architecture/03-safety.md)。

## 起因

S1 的 32 次地面任务中有 2 次停滞（`f0849ca` 的 `x1_cancel_during_recheck-19`、`2710869` 的 `x1_link_loss_driving-19`）：

- PX4 打印 `Executing Mission`，导航器已把位置设定点三元组切到下一个航点（`current.valid=1`），但地面车的位置控制器始终保持起点的「保持」设定点，电机输出为 0；
- 180 s 后 `nav_to` 超时，executive 中止，guardian 停车并在静止后上锁，任务记为未完成，复核为 unknown；
- 两次的首个航点都是地图坐标 (0.625, 1.875)；同方位、首段更长的 (0.875, 2.625) 六次全部正常。

## 三个探针

都在当前部署的 X1 仿真镜像里运行，客户端只连地面车（实例 1），主机侧持项目锁（非阻塞获取），结束后删除容器。

| 探针 | 做法 | 任务数 | 停滞 |
|---|---|---|---|
| 1 | 同一会话、只解锁一次，交替三种两点任务：带改速项（S）、不带改速项（N）、不带改速项但启动后发改速命令（K） | 90 | 0 |
| 2 | 每轮新会话（如同新的 guardian）：保持、解锁、等 1.5 s、上传从车所在处出发的航线、启动；首轮把 `RO_SPEED_LIM` 设为 1.0 | 50 | 0 |
| 3 | 每次新启动 X1 世界、从停车位朝北出发：A 为卡住的几何、B 为正常的几何、C 只有那一个短段 | 10 | 0 |

停滞没有复现，原因仍未查明。

## 顺带发现：限速没有生效

- 探针 1 中三种做法的峰值估计速度都在 1.86–1.98 m/s。MAVSDK 把改速项插在航点**之后**，第一段行驶时它还没生效，地面车按 PX4 默认的 `RO_SPEED_LIM` 1.8 m/s 行驶。
- S1 中，从车所在处出发的航线第一段长度为零，改速项随即生效：`f0849ca` 上的真值速度（0.5 s 窗口）峰值为 1.000–1.007 m/s。`fc6dd6d` 去掉了起始航点，`2710869` 上的真值峰值因此升到 1.62–1.80 m/s，超出平台声明的 1.0 m/s。
- 探针 2 把 `RO_SPEED_LIM` 设为 1.0 后，峰值估计速度为 1.18 m/s（估计值的瞬时尖峰）。

## 处置

- 撤回「去掉起始航点」。
- X1 仿真的地面车机架设置 `RO_SPEED_LIM 1.0`。适配器上传航线前读取飞控限速，高于平台最大速度或读不到即拒绝行驶。
- S1 裁判新增「地面车超速」计数：真值速度超过平台最大速度加 0.2 m/s 即计入，人为送回的瞬间除外。
- 停滞按设计由超时与机载中止收尾，适配器不加未经真实故障验证的重启补救。S1 再出现时，该批不计入、同版本重跑，并在验收记录中写明。

原始结果在 `probe1_result.json`、`probe2_result.json`、`probe3_result.json`，脚本为 `probe*_client.py` 与 `probe*_host.py`（探针 2 的主机侧即探针 1 的主机脚本，只换了工作目录、容器名与轮数）。
