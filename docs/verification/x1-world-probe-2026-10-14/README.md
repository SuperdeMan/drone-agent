# X1 世界探针（2026-10-14）

这是 [X1 实施方案](../../x1-implementation.md) §14「S1 世界与编排」写编排之前的实测。它只是一次测量，不是发布门禁，也不计入任何验收。

## 怎么测的

- **镜像**：以 `drone-agent-m1-aircraft:6249129…`（PX4 v1.17.0，`d6f12ad1`）为基础，加入当时的 `sim/x1_setup.py` 与 `sim/x1_sitl.sh`，临时构建，测完即删。
- **世界**：实例 0 为 x500，实例 1 为差速车（standalone，生成于 (2, −4)、朝北）；两路 `sim/collect.py` 转接相机与真值。
- **方块**：在地面车正前方约 3 m 放 5 个 0.6 m 方块：橙色与品红，各一个按声明值、一个按声明值的 2.2 次幂作自发光（漫反射为黑）；另加一个普通受光的橙色方块。
- **行驶**：探针客户端（`world_client.py`，机载镜像的 MAVSDK 3.17.4，只连实例 1）读取参数，解锁，向东行驶 2.5 m，Hold，上锁。
- **日志**：探针时把地面车的 `SDLOG_MODE` 临时设为 2（从启动记到关机），以便看到完整的解锁迁移；`ulog_extract.py` 取出 `vehicle_status` 的迁移与本地位置。
- **主机侧**：`world_probe_host.py` 持项目锁运行（非阻塞获取），`make_probe.py` 生成自包含的启动脚本；结束后删除容器与临时镜像。

## 结果

| 项 | 实测 | 对设计的影响 |
|---|---|---|
| 模型与话题 | 地面车模型 `rover_differential_1`，前视相机话题 `/world/default/model/rover_differential_1/link/front_camera/sensor/cam_0/image` | 采集器与地面图按此配置 |
| 参数 | `SIM_BAT_DRAIN` 1800、`MAV_SYS_ID` 1、`SYS_AUTOSTART` 50000 | 设置生效 |
| home | 实例 0 约 14 s、实例 1 约 20 s 设好 home | 编排等两者都设好再继续 |
| 自发光颜色 | 声明值 (1, 0.549, 0) 成像为 (255, 195, 0)；2.2 次幂 (1, 0.267, 0) 成像为 (255, 141, 0)。品红声明值成像 (244, 0, 244)，2.2 次幂成像 (231, 0, 231)。受光橙色为 (201, 153, 0) | Gazebo 按 sRGB 编码自发光；方块取 2.2 次幂、漫反射为黑，成像即声明颜色，定位器（容差 40）可用 |
| 前视测距 | 方块前面距相机 2.25 m 时，与地面相接的行为 81，与声明相机（离地 0.5 m、80°）的计算值 81.19 一致 | 相机几何与声明一致 |
| 日志时钟 | 日志中运动起点 21.912 s，Gazebo 真值运动起点仿真时间 21.876 s（真值 20 Hz） | 日志时钟即仿真时间，裁判按仿真时间对齐 |
| 日志大小 | `SDLOG_MODE` 2 约 215 KB/s（26.5 s 写了 5.7 MB） | 一个 S1 用例会有约 200 MB；改回 PX4 默认（只在解锁期间记录，每个解锁期一个文件），裁判把文件跨度当作解锁区间 |

## 与本记录之后的差别

- 探针时前视相机装在车头前 0.45 m；地面图没有声明前向偏移，之后改为装在车体参考点正上方。
- 探针时地面车用 `SDLOG_MODE` 2；镜像之后保持 PX4 默认。

原始结果：`report.json`（编排记录）、`client.json`（参数、事件与 0.2 s 一次的位置样本）、`ulog1.json`（日志迁移与位置）、`rover-truth.jsonl`（地面车 Gazebo 真值）、`frames/g_blocks.json`（放置方块后的前视画面）。
