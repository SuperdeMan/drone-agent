# P6 完整道路目标标注

本入口供用户本人建立独立业务标注，承接 D089。它只展示原图和拍摄元数据，不展示模型回答、源道路类别或 AI 边界草稿。新素材仍属于待筛选池；登记完成也不自动成为正式测试样本。

## 操作顺序

1. 填写实际复核者，开始标注计时。计时只累计页面可见、聚焦且有交互的时间；切换图片、切走页面或主动暂停会停止。这里测量的是标注制作时间，不是 D089 的候选复核耗时。
2. 先用地标描述检查哪一段道路，画出完整目标区域，再确认目标定义。不要根据已经发现的障碍缩小检查范围；修改目标定义后必须重新确认并复查整幅目标。
3. 查看整个目标，选择正常、有实体遮挡或不可判。选择有实体遮挡时圈出支撑判断的实体或实体群，登记 `debris`、`vegetation` 或 `other_entity`。不设物体大小门槛，阴影、标线、路面破损不按实体计；普通车辆缺少阻碍上下文时保留不可判。
4. 无法从图片确定可用道路时，可以登记“素材不适用”，写明原因；它不自动成为错目标测试。`wrong_target` 只允许已有独立任务定义和可追溯任务依据、但影像没有呈现该目标的情况，不能用“图片没有道路”代替。
5. 如实登记是否已看过该图的模型回答或源类别标签。GPS、相机日期和相似图索引只是分组线索；不确定资产、地点或批次时留空，不为凑样本数创建独立身份。
6. 保存本条并导出 JSON。离线包身份、图片摘要、目标定义、依据、复核者、时间和提示暴露随记录导出。浏览器缓存只是便利机制，应及时导出。

## 数据与审查边界

- 全部目标定义和整图结论由实际复核者填写；没有预填业务答案。已取得文件头但缺完整原图的条目不进入页面。
- 正常 / 有障碍必须有确认的完整目标；有障碍必须有支撑实体几何及类型。局部实体登记不能自动生成整图正常。
- 分组字段允许未知；只有明确填写真实身份和依据后才可声明分组已核对。图片编号、GPS 连接组、相机日期都不自动提升为资产 / 地点 / 批次。
- 导入脚本核对受信包摘要、UI / 图片摘要、记录结构与几何。输出是新的未分配拆分草案，先完成独立身份和拆分，再交给 `p6_business_eval.py audit`；草案格式本身不被正式审计入口接纳。不替操作者宣布真实性认证，也不自动批准正式清单。
- QA 包有独立标识；自动化测试导出不进入人工标签数量。标注会话不会转换成候选复核会话，后续真实模型输出的复核需单独计时。
- 新素材在测试身份确定和画像冻结之前保持隔离；代码及浏览器测试使用明确的人工合成 QA 图，不查看隔离素材来调提示。

实施入口为 `scripts/p6_road_labeling.py` 的 `build` / `import`，页面资源位于同名目录。包保存在仓库外，原图不进 Git。实际包路径、摘要、验证及尚未完成的工作更新到[当前交接](p6-materials-handoff-2026-10-15.md)。
