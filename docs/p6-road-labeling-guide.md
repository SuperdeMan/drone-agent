1. 在 Windows 文件资源管理器地址栏粘贴 `D:\drone-agent-data\p6-business-closeout-20261015\labeling-human-v1\index.html`，按回车，用 Chrome 或 Edge 打开。这是第一批 118 张；后续第二批入口为同级 `labeling-human-v3\index.html`，297 张。保留整个素材目录，不要只移动 HTML 文件。

3. 每张完成后点右侧底部 **「保存本条标注」**，看到「已登记」或「本条已保存」才算保存成功。如果提示缺字段，补齐后再次保存；只填表或只画轮廓仍是草稿。
4. 点页面右上角 **「导出标注」**。浏览器会下载 `p6-road-labels-时间.json`；页面会提示导出了多少条已保存记录。导出包含本包全部已保存记录，不包含未保存草稿。若提示 0 条，先返回完成并保存至少一条。
5. 按 `Ctrl+J` 打开浏览器下载列表，找到刚下载的 JSON，点「在文件夹中显示」。在文件资源管理器中右键该文件，选择「复制文件地址」；如果没有该项，可按住 Shift 再右键选择「复制为路径」。把完整路径发回对话，例如 `C:\Users\Super\Downloads\p6-road-labels-2026-10-16T…json`，收到后再执行校验导入。不要手动改写 JSON。

后续可继续在同一浏览器、同一路径打开页面；草稿会尝试从本机缓存恢复，已导出的文件可作备份。换浏览器或缓存丢失时，在对应素材包页面点 **「导入记录」**，选择该包的导出文件。两批分别保存和导出，不要把第一批文件导入第二批页面。

## 操作顺序

1. 填写实际复核者，开始标注计时。计时只累计页面可见、聚焦且有交互的时间；切换图片、切走页面或主动暂停会停止。这里测量的是标注制作时间，不是 D089 的候选复核耗时。
2. 先用地标描述检查哪一段道路，点「画目标范围」，在图上沿完整道路区域逐点点击至少三个不共线的顶点，点「完成轮廓」，再点「确认目标定义与轮廓」。不要根据已经发现的障碍缩小检查范围；修改目标定义后必须重新确认并复查整幅目标。
3. 放大并查看整个目标，选择正常、有实体遮挡或不可判，写明「判断依据 / 不可判原因」。选择有实体遮挡时，先在工具栏选择「散落 / 堆积物」「侵入植被」或「其他实体」，点「圈实体」，沿实体轮廓逐点点击，再点「完成轮廓」；需要时重复圈其他实体。检查结束后勾选「已检查整个确认目标」。不设物体大小门槛，阴影、标线、路面破损不按实体计；普通车辆缺少阻碍上下文时保留不可判。
4. 无法从图片确定可用道路时，可以登记“素材不适用”，写明原因；它不自动成为错目标测试。`wrong_target` 只允许已有独立任务定义和可追溯任务依据、但影像没有呈现该目标的情况，不能用“图片没有道路”代替。
5. 如实登记是否已看过该图的模型回答或源类别标签。GPS、相机日期和相似图索引只是分组线索；不确定资产、地点或批次时留空，不为凑样本数创建独立身份。
6. 保存本条并导出 JSON。离线包身份、图片摘要、目标定义、依据、复核者、时间和提示暴露随记录导出。浏览器缓存只是便利机制，应及时导出。

## 数据与审查边界

- 全部目标定义和整图结论由实际复核者填写；没有预填业务答案。已取得文件头但缺完整原图的条目不进入页面。
- 正常 / 有障碍必须有确认的完整目标；有障碍必须有支撑实体几何及类型。局部实体登记不能自动生成整图正常。
- 分组字段允许未知；只有明确填写真实身份和依据后才可声明分组已核对。图片编号、GPS 连接组、相机日期都不自动提升为资产 / 地点 / 批次。
- 导入脚本核对受信包摘要、UI / 图片摘要、记录结构与几何。输出是新的未分配拆分草案，先完成独立身份和拆分，再交给 `p6_business_eval.py audit`；草案格式本身不被正式审计入口接纳。不替操作者宣布真实性认证，也不自动批准正式清单。
- QA 包有独立标识；自动化测试导出不进入人工标签数量。标注会话不会转换成候选复核会话，后续真实模型输出的复核需单独计时。
- 新素材在测试身份确定和画像冻结之前保持隔离；代码及浏览器测试使用明确的人工合成 QA 图，不查看隔离素材来调提示。
- 多批导入草案可能具有不同的 `data_root`。正式汇总时需统一图片、许可、AI 原稿和操作员导出路径，保留原摘要；核对原隔离登记在累积登记中的原项后，再绑定批准的累积摘要，不改写原始导出。
