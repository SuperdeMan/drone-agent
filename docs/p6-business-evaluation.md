# WP-P6-01 道路业务评测实施

本任务集中完成目标业务的数据、标注、计分和准出证据，不改变飞行控制或生产画像。用户于 2026-10-15 指定由本人承担业务复核；这表示复核责任已确定，尚不表示任何样本已获确认。现有 62 张开发照片、26 条开发条目和 33 个模型提案继续保留开发属性。

## 工作与冻结顺序

1. 核验来源许可、图像字节、地点 / 资产 / 批次及近重复组；未知元数据保留缺失，不生成虚构的独立地点。
2. 由用户复核目标范围与业务标签，记录判断依据和提示暴露；标注用时与候选复核用时分开。旧 v6 道路 / 实体记录只能补充几何，不能推出整图正常。
3. 按完整关联组隔离开发、校准和测试，冻结样本量、指标定义与准出判据；没有获确认的数值不写成已批准阈值。
4. 完成道路专用分析入口与校准，再冻结画像和实际调用参数。原设备变化画像要求正常参考图，不能把道路提示图伪装成“正常参考”。
5. 按预登记次数实调、严格回放和计分，报告缺失项、失败项及影响范围，补齐候选验证后形成关闭结论。

## 标注规范草案

基本单元为一次指定道路目标的影像观察，关联真实 `asset_id`、`site_id`、`capture_batch_id` 和图像摘要。多个窗口、裁剪、同图两个目标及近邻帧不能自动成为独立资产或采集批次。

| 标签 | 定义 |
|---|---|
| `normal` | 已检查完整目标范围，未发现符合当前口径的实体遮挡；未检查或看不清不能选此项。 |
| `obstacle` | 有可辨认的实体或实体群实际进入指定道路范围；无物体最小尺寸 / 占用比例门槛。单件难以分离或材质细类未知不自动否定存在。 |
| `indeterminate` | 实体存在、目标边界或图像质量不足以支持确定判断；必须写原因。 |
| `wrong_target` | 可信任务定义与影像不匹配，或所需道路目标没有出现在影像中；不能仅凭源数据没有道路标签推断。 |

普通车辆出现不自动构成障碍；缺少判断其阻碍关系的上下文时保留不可判。阴影、标线、路面破损与实体分开。标签必须包含实际复核者、依据、时间、是否看过模型 / 源标签提示及是否完成整个目标检查。AI 建议、源分割类别和 QA 夹具均不能自行升级为本业务人工标签。

类型词表、困难类别覆盖和数量目标见下文已采用的 D089；实际样本及其拆分仍待冻结。主分类评测与对象级定位评测分开，不能用一个宽框命中多个对象来宣称对象召回率。

## 用户已采用的第一版验收目标

以下工程验收目标于 2026-10-15 经用户回复“采用这版目标，继续补齐数据”确认。**目标已采用，数据清单和正式运行范围尚未冻结；这些不是行业标准，也不是现有模型已达到的成绩。** 原工作包要求建立目标业务评测并报告五类指标；本协议把“满足什么结果才采用”明确下来，不能从 P4 电路板成绩直接继承。验收用于有人复核的道路障碍候选筛查，不用于无人值守的安全通行判断。

| 项目 | 已采用要求 | 计分约束 |
|---|---|---|
| 正常目标误报 | 每 100 个正常资产 ≤ 5 次 | 每个资产只有一个预先指定的主观察；正常分母至少 100；另报全部可判资产分母 |
| 按类型漏检 | 每类 ≤ 20% | 障碍主观察至少 100，每个已冻结类型至少 30；拒判计入漏检，错类型也计入该类型漏检 |
| 确定性样本覆盖 | ≥ 90% | 分母为真值正常 + 有障碍；不能通过大量拒判回避误报 / 漏检 |
| 不可判 / 错目标被判正常 | 0 次 | 两类各至少 30；这里的零是样本内零次，不表示真实错误概率为零 |
| 跨次稳定性 | 可判且结论一致的配对 ≥ 90% | 至少 30 对，覆盖至少 15 个不同资产；须为同资产、同状态、不同真实采集，双拒判不算成功 |
| 人工复核负担 | 有效查看时间 p95 ≤ 120 秒 | 所有候选 / 拒判主观察都需真实计时，至少 30 条；报告中位数、p95、总用时和覆盖率 |

初始测试集至少 **260 个不同资产的主观察**（正常 100 + 障碍 100 + 不可判 30 + 错目标 30），另有满足配对要求的重复采集；不能靠裁剪、同图多个窗口或同一资产多拍扩充主观察分母。测试覆盖至少 3 个经核对的地点，任一地点不超过主观察的 50%。校准集另需至少 60 个主观察（20 + 20 + 10 + 10），与测试及开发在资产、地点、批次和近重复组上完全隔离。首版缺陷词表为 `debris`（非植被的散落 / 堆积物）、`vegetation`（侵入道路的植被）、`other_entity`（其他已确认的实体），不得把同一实体重复填多个类型以凑覆盖；同图多个不同类型可以同时记录。

这些样本量是首次 S2 的可审查起点，不足以证明上述门槛在所有道路上都有统计保证。所有比例同时报告分子、分母和 Wilson 95% 区间；例如 100 个正常资产有 5 次误报，其区间上界约 11.2%，并不能证明总体误报率的上界为 5%。本轮判据采用预登记的观察值，区间如实披露；若要求置信上界也达标，需要另行设计更大样本，不能在跑完测试后切换统计口径。

用户同时承担真值标注和候选复核时，第二阶段必须记录已经看过真值，报告为“熟悉样本的复核耗时”；该计时不代表陌生操作员效率。标注目标、查找所有实体的时间独立记录，不能混入日常候选复核。重复回看不增加独立复核样本数。

真实清障效果仍未验证；用户已另行确认本工作包按 S2 范围验收（见文末范围澄清）。跨次同状态配对不替代清障效果，静态图片不证明现场处置。实际数据清单、画像和运行次数仍须在正式测试前冻结。`protocol-draft.json` 记录实际用户确认，状态为 `targets_approved_data_pending`；不能提前改为 `frozen`。数据或结果未达标时保留 `missing` / `failed`，不追着测试成绩降阈值。

## 五类指标的计分约定

- **误报**：同时报告正常观察中误报数、正常观察总数和每 100 次正常资产观察的误报数；另报每 100 次全部确定性观察的误报数，避免分母混淆。每资产 / 每地点样本数单列。
- **按类型漏检**：对包含某类障碍的观察，报告未报候选的比例，以及未正确给出该类型的比例；这是观察级指标，不冒充实例级召回率。拒判也进入漏检分母，不靠全部拒判得到好成绩。
- **拒判与原因**：报告总拒判率、确定性样本覆盖率和原因分布；将不可判 / 错目标错误输出为正常单列。没有结果不能自动记作正常。
- **跨次稳定性**：只使用经复核确认同资产、同状态的不同真实采集对；同时报告双方可判覆盖率、可判结论一致率及未解决对。双方都拒判不算稳定性成功，重复文件不算新采集。
- **人工复核用时**：只统计真人的候选 / 拒判复核会话，报告样本数、覆盖率、中位数和 p95，并区分提示 / 既有标签暴露。制作真值的标注时间另列，不混作日常复核效率。

所有百分比同时保留分子 / 分母。没有分母时返回缺失，不填 0；脚本和回放只能验证计算链路，不计成新的实调成绩。模型调用必须另有冻结来源与严格回放证据，单凭导入一张结果表不能准出。

跨次稳定性是对称比较，分两种证据范围报告：有可信时区和时刻的有序采集，或 `distinct_original_captures_unordered` 的不同原始实拍。后一种须分别绑定源影像编号、完整原图摘要及已校验源清单，并由真人确认不同采集、同一资产、同一状态；不补造 UTC，不声明时间先后、间隔或隔日稳定性。对同一张图裁剪 / 重编码不构成新采集，缺少源清单或人工确认仍不接纳。它不改变 D089 的 30 对 / 15 个资产要求，也不用于证明清障因果。

## 当前实现边界

本轮先落地离线数据准入和计分核心，入口为 `scripts/p6_business_eval.py`。协议位于 `eval/s2/road_business_v1/protocol-draft.json`；即使验收目标已批准，实际样本、独立标注和冻结清单未齐时仍保持 `missing`。它不启动模型、服务或数据库迁移。

该核心已在 `b56b851` 冻结。`audit` 检查原图 / 许可摘要、人工标签、目标几何、曝光记录、跨集合关联、主观察数量和 D089 覆盖要求；`score` 要求选定集合的每张观察都有且只有一条同图摘要的模型结果；`assess` 对照已采用目标。三者均不授予最终准出；计分输入表不能自行证明来源于冻结模型实调。无分母、缺人类计时或欠缺任一类型时，不填零凑齐结果。

在仓库根目录复算已有开发材料的缺口（输出必须使用新的文件名）：

```powershell
uv run --frozen python scripts/p6_business_eval.py audit --manifest eval/s2/road_business_v1/development-manifest.json --labels eval/s2/road_business_v1/labels-template.json --protocol eval/s2/road_business_v1/protocol-draft.json --exposure eval/s2/road_business_v1/exposure-registry.json --data-root D:/drone-agent-data --output D:/drone-agent-data/p6-business-eval-20261015/development-audit-next.json
```

`labels-template.json` 是空白登记模板，不能作为已经完成的人工标签提交。实际计分文件依次使用 `drone.p6-road-corpus/v1`、`drone.p6-road-labels/v1`、`drone.p6-road-predictions/v1` 和 `drone.p6-road-review-sessions/v1`，四份 `corpus_id` 必须一致。预测行包含 `sample_id`、`image_sha256`、`verdict`、`defect_types`、`reasons`；候选类型不能为空，正常 / 拒判的类型为空，拒判保留原因。真实计时行必须有 `phase=candidate_review`、`origin=human`、实际复核者、起止时间、有效毫秒数及提示 / 真值暴露标记。空白、QA 和标注制作记录不参与复核效率。

数据和真实运行齐全后使用下列命令；文件名为待生成产物，不表示现在已有这些结果：

```powershell
uv run --frozen python scripts/p6_business_eval.py score --manifest <frozen-manifest.json> --labels <human-labels.json> --predictions <recording-derived-predictions.json> --reviews <human-candidate-reviews.json> --split test --output <new-metrics.json>
uv run --frozen python scripts/p6_business_eval.py assess --protocol <frozen-protocol.json> --metrics <new-metrics.json> --output <new-comparison.json>
```

复核者入口沿用[边界登记操作说明](p6-boundary-review-guide.md)：先完成 6 个道路区域 / 13 组开发实体并导出 JSON。该导出只证明实际登记的边界和实体关系，不能由程序推断整幅道路没有遗漏，也不能自动充当尚未建立的正式测试标签。新素材待完成来源、分组和整目标标注清单后再进入正式评测。

正式道路分析入口、校准及唯一冻结测试仍依赖合格数据与人工记录，不把已有逐提案探针当成穷尽整个道路的识别结果。使用权、独立性、跨次及实际复核证据未齐时不关闭 WP-P6-01。真实清障效果不属于本工作包 S2 准出范围，也不从静态图或模拟结果推断已验证。

## 完整道路 S2 接入

道路评测使用独立的绝对状态识别协议 `road-whole-target-eval-v1`。输入为原图和中性的已登记目标轮廓；轮廓图不被称为正常参考，不复用设备变化画像来表达“正常—异常差异”。该入口只用于 S2 素材评测，不更换任务台在用画像。

模型任务与真值分文件：`drone.p6-road-model-tasks/v1` 只包含样本 / 图片身份、目标描述、目标轮廓、事先登记时间、登记依据和来源。所有被评测观察都必须有完整的任务定义，不能仅给正常 / 障碍样本画轮廓，再利用拒判类缺轮廓来偷看答案。正式任务登记时间不得晚于业务标签时间，QA 来源不得进入正式运行。模型请求不包含业务标签、实体圈绘、人工判断依据或源道路类别。

`scripts/p6_road_s2.py` 负责输入制备、响应校验和录制回放；原图、目标提示与实际模型输入分别保存摘要。任何影像解码 / 摘要问题直接停止制备，不能悄悄删样本。模型回答中的图像、目标可见性、边界不确定与实体不确定分别记录；空回答、非法 JSON、错模型、低置信度和协议不合格都映射为明确拒判，并保留原因进入既有计分分母。

开发制备可以使用明确的 QA / 开发任务，但不产生准出资格。校准和测试制备必须重算 D089 数据准入；正式协议、独立标签和样本覆盖不完整时，在任何模型调用前停止。测试另需已经选择并冻结的画像和校准记录。实调只允许通过云端隔离执行与冻结录制流程；本地回放仅复算记录，不增加调用次数。最终模型测试与业务准出仍以真实冻结运行证据为准，不能从软件夹具推断模型能力。

云端入口 `p6_road_s2_cloud.py launch` 默认只返回计划，显式 `--apply` 才上传并启动有界后台执行器；`status` / `fetch` 只查状态和取回证据。冻结登记位于 `eval/s2/road_business_v1/frozen/<批次>/`，必须包含同候选的源码、制备计划、模型输入清单、画像，以及摘要绑定的源清单 / 任务 / 标签 / 协议 / 曝光登记；原图仍在仓库外。正式测试还须校准实调、严格回放和选择记录，而不是只写一个“校准通过”字段。选择记录用 `canonical_sorted_json/v1` 绑定完整校准回放，保存实际决策原因及相对于记录文件的 `calibration_package` / `calibration_cloud` 路径；测试制备会重新核对实际校准证据。

执行器复用已有项目锁、固定运行时镜像和只读模型密钥，不挂载控制接口，不修改常驻服务。正式测试会先在云端 `~/drone-agent/data/p6-road-test-exposure-v1/` 以不可覆盖文件占用影像 / 关联组标识；换目录、换画像不能重用。开始之后状态不明时只核对并取回原尝试，不自动重跑；仅明确的锁忙零调用允许新尝试。占用记录遇故障保守保留，不自动删除或当作测试从未开始。

最终门禁为 `scripts/verify_p6_road_business.py`：重新执行数据准入，核对确切候选源码与全量软件验证、校准和测试的独立冻结输入、真实模型身份、持锁及常驻环境前后快照、逐例严格回放与映射一致性，再计算 D089 五类指标和实际人工复核时间。另报告模型 token、时延和 `unpriced` 费用状态。缺任何证据为 `missing` / `not_passed`；全套数值与来源满足后才允许 `wp_p6_01_closed=true`，范围始终是已批准的 S2。
