## 标注规范草案

基本单元为一次指定道路目标的影像观察，关联真实 `asset_id`、`site_id`、`capture_batch_id` 和图像摘要。多个窗口、裁剪、同图两个目标及近邻帧不能自动成为独立资产或采集批次。

| 标签 | 定义 |
|---|---|
| `normal` | 已检查完整目标范围，未发现符合当前口径的实体遮挡；未检查或看不清不能选此项。 |
| `obstacle` | 有可辨认的实体或实体群实际进入指定道路范围；无物体最小尺寸 / 占用比例门槛。单件难以分离或材质细类未知不自动否定存在。 |
| `indeterminate` | 实体存在、目标边界或图像质量不足以支持确定判断；必须写原因。 |
| `wrong_target` | 可信任务定义与影像不匹配，或所需道路目标没有出现在影像中；不能仅凭源数据没有道路标签推断。 |

## 五类指标的计分约定

- **误报**：同时报告正常观察中误报数、正常观察总数和每 100 次正常资产观察的误报数；另报每 100 次全部确定性观察的误报数，避免分母混淆。每资产 / 每地点样本数单列。
- **按类型漏检**：对包含某类障碍的观察，报告未报候选的比例，以及未正确给出该类型的比例；这是观察级指标，不冒充实例级召回率。拒判也进入漏检分母，不靠全部拒判得到好成绩。
- **拒判与原因**：报告总拒判率、确定性样本覆盖率和原因分布；将不可判 / 错目标错误输出为正常单列。没有结果不能自动记作正常。
- **跨次稳定性**：只使用经复核确认同资产、同状态的不同真实采集对；同时报告双方可判覆盖率、可判结论一致率及未解决对。双方都拒判不算稳定性成功，重复文件不算新采集。
- **人工复核用时（后续运营验证）**：只统计真人的候选 / 拒判复核会话，区分提示 / 真值暴露。2026-10-18 经用户确认从本次门槛移出；当前明确为未验证，不用 AI 标注时间推算效率。

所有百分比同时保留分子 / 分母。没有分母时返回缺失，不填 0；脚本和回放只能验证计算链路，不计成新的实调成绩。模型调用必须另有冻结来源与严格回放证据，单凭导入一张结果表不能准出。

跨次稳定性是对称比较，分两种证据范围报告：有可信时区和时刻的有序采集，或 `distinct_original_captures_unordered` 的不同原始实拍。后一种须分别绑定源影像编号、完整原图摘要及已校验源清单，并由获授权的复核者确认不同采集、同一资产、同一状态及可比较的目标范围；AI 复核另绑定独立登记和逐对记录，不写成真人确认。不补造 UTC，不声明未经证实的时间先后、间隔或隔日稳定性。同图裁剪 / 重编码不构成新采集，缺少源清单或真实复核证据仍不接纳。D089 的 30 对 / 15 个资产要求不变，也不用于证明清障因果。

## 完整道路 S2 接入

道路评测使用独立的绝对状态识别协议 `road-whole-target-eval-v1`。输入为原图和中性的已登记目标轮廓；轮廓图不被称为正常参考，不复用设备变化画像来表达“正常—异常差异”。该入口只用于 S2 素材评测，不更换任务台在用画像。

模型任务与真值分文件：`drone.p6-road-model-tasks/v1` 只包含样本 / 图片身份、目标描述、目标轮廓、事先登记时间、登记依据和来源。所有被评测观察都必须有完整的任务定义，不能仅给正常 / 障碍样本画轮廓，再利用拒判类缺轮廓来偷看答案。正式任务登记时间不得晚于业务标签时间，QA 来源不得进入正式运行。模型请求不包含业务标签、实体圈绘、人工判断依据或源道路类别。

正式制备和最终门禁还逐条核对模型任务与真值所对应的图片、目标描述和目标轮廓完全一致；仅有相同图片编号不够。输入原图必须使用无隐式 EXIF 旋转的坐标系，否则先完成明确的规范化和重新登记；不能让浏览器显示与模型处理采用不同方向。

`scripts/p6_road_s2.py` 负责输入制备、响应校验和录制回放；原图、目标提示与实际模型输入分别保存摘要。任何影像解码 / 摘要问题直接停止制备，不能悄悄删样本。模型回答中的图像、目标可见性、边界不确定与实体不确定分别记录；空回答、非法 JSON、错模型、低置信度和协议不合格都映射为明确拒判，并保留原因进入既有计分分母。

开发制备可以使用明确的 QA / 开发任务，但不产生准出资格。校准和测试制备必须重算 D089 数据准入；正式协议、独立标签和样本覆盖不完整时，在任何模型调用前停止。测试另需已经选择并冻结的画像和校准记录。实调只允许通过云端隔离执行与冻结录制流程；本地回放仅复算记录，不增加调用次数。最终模型测试与业务准出仍以真实冻结运行证据为准，不能从软件夹具推断模型能力。

云端入口 `p6_road_s2_cloud.py launch` 默认只返回计划，显式 `--apply` 才上传并启动有界后台执行器；`status` / `fetch` 只查状态和取回证据。冻结登记位于 `eval/s2/road_business_v1/frozen/<批次>/`，必须包含同候选的源码、制备计划、模型输入清单、画像，以及摘要绑定的源清单 / 任务 / 标签 / 协议 / 曝光登记；原图仍在仓库外。正式测试还须校准实调、严格回放和选择记录，而不是只写一个“校准通过”字段。选择记录用 `canonical_sorted_json/v1` 绑定完整校准回放，保存实际决策原因及相对于记录文件的 `calibration_package` / `calibration_cloud` 路径；测试制备会重新核对实际校准证据。

执行器复用已有项目锁、固定运行时镜像和只读模型密钥，不挂载控制接口，不修改常驻服务。正式测试会先在云端 `~/drone-agent/data/p6-road-test-exposure-v1/` 以不可覆盖文件占用影像 / 关联组标识；换目录、换画像不能重用。开始之后状态不明时只核对并取回原尝试，不自动重跑；仅明确的锁忙零调用允许新尝试。占用记录遇故障保守保留，不自动删除或当作测试从未开始。

最终门禁为 `scripts/verify_p6_road_business.py`：重新执行数据准入，核对确切候选源码与全量软件验证、校准和测试的独立冻结输入、真实模型身份、持锁及常驻环境前后快照、逐例严格回放与映射一致性，再计算 D089 当前范围内的质量和覆盖指标。真人复核时间仅在有明确延期批准时单列未验证、从本次门槛移出；没有批准则仍须真实记录。另报告模型 token、时延和 `unpriced` 费用状态。缺少在范围内的证据仍为 `missing` / `not_passed`，全部满足后才允许 `wp_p6_01_closed=true`。

### 正式运行前固定的无回答重试

`de07338` 增加的 `unanswered-only-v1` 在首次正式冻结前按 [D090](decisions.md#d090--道路-s2-无回答重试与证据路径解析)登记：每观察最多 3 次尝试，重试至少退避 60 / 120 秒并服从服务端限流；只有没有录得回答的尝试可以重试。录得任何回答后不再重问，格式错误、拒判或低置信度继续进入原有计分口径。连续 2 个观察未成功则停止整轮。所有开始标记、失败和最终录制进入门禁记账；停止后保留测试曝光，不自动重启整个测试。该策略尚不构成模型实调或业务准出成绩。
