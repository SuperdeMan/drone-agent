# M1 实施与验收计划

本轮落实路线图的六项 M1 任务。范围是云端 PX4 1.17.0 / Gazebo Harmonic 单机仿真，不接大模型，不连接真机。M0 的历史证据、15 条恢复边草案与原注入矩阵保留；它们不能被新运行时的测试结果追认。

## 实施顺序

| 批次 | 实现 | 验收 |
|---|---|---|
| A：本地权威状态 | 同步落盘的追加日志、命令对账、重启代次隔离、类型化 protobuf 编解码、本地认证 IPC、观测与时钟 | 崩溃窗口、日志损坏、重复键载荷冲突、过期/乱序心跳、权限与 wire 往返测试 |
| B：安全闭环 | guardian 单一出口、独立监督周期、已批准地图登记表、恢复图、五技能注册表、DAG 与取消/暂停 | 真实状态机、资源占用、unknown 阻断、恢复优先级及每条策略边的注入测试 |
| C：仿真与裁判 | MAVSDK 适配器、Gazebo 相机、独立真值采集、sim/aircraft/ground 三镜像、MCAP 与回放 | 云端真实起飞、逐航点、影像、返航等待、落地；裁判与被测进程隔离 |
| D：准出 | 固定场景 DSL、至少三个种子、云端故障矩阵、证据索引 | 零错误成功报告；关键故障全部通过；proto v1 冻结；精确 SHA、镜像、配置哈希与基线归档 |

## 运行时设计

- M1 的输入是由本地可信操作入口提供、已审批的固定任务包；不提前实现 M2 Planner。executive 与 guardian 分别复核包哈希、时间窗、机器人、技能参数、资源及登记表引用。任务包文件是 M1 仿真的本地信任根；不把普通哈希宣称为数字签名。
- IPC 使用 protobuf/gRPC，本机 Unix socket 目录权限为 0700，使用 gRPC local credentials。guardian 启动时绑定允许的 executive 身份及任务包；不监听公网 TCP。Windows 的纯 IPC 测试可使用受 local credentials 约束的回环地址。
- 权威账本采用带序号和前项哈希的 JSONL，命令进入适配器前先 fsync 记录 intent 和代次水位；完成后再记录 receipt。断电留下的 inflight 结果为 unknown，不自动重发。重启后旧会话必须换代次，且不能自动恢复飞行。
- UTC 用于审批/租约/wire；进程存活与接收新鲜度用单调时钟，Gazebo 仿真时间用于轨迹/证据对齐。加速因子不延长真实进程 watchdog；必须分别报告实际仿真速度与监督周期。
- 共享云主机的验收配置采用 1× 请求速度；`--speed-factor 2` 保留加速入口，实际倍率由真值时钟与 UTC 时长计算。2× 请求在现有 1.5 CPU 仿真配额下曾出现大于 500 ms 的遥测间隙，作为负结果保留，不放宽新鲜度阈值。
- M1 只启用 mission_upload；所有 offboard 意图均在适配器之前拒绝。业务 return_home 上传登记航线并停在 home 等待点；恢复 rtl 才调用飞控原生 RTL。
- guardian 的恢复动作也经过持久化的控制出口。用户暂停必须等待 hold 的新鲜观测；取消请求与 recovered_to 分开。外部模式接管和飞控失效保护优先于任何软件恢复，不重夺控制。
- M1 使用单独的 mission-upload 恢复策略，覆盖实际具备的定位/能源上下文；缺上下文不能猜测可达性。M0 中依赖视觉定位、Offboard 的分支保留为未来草案，单测覆盖不计为物理验证。
- 地图登记表包含体积、航线、home、降落点、资产和阈值，并绑定版本与内容哈希。最小场景使用无遮挡凸体积和预验证航线；不能宣称具备 M3 障碍避让或通用能源可达性。
- 相机输出必须是真实 Gazebo RGB 传感器帧。运行时只读取图像、飞控估计与登记地图；Gazebo 真值仅交给 ground 裁判。缺帧、缺位姿不确定性、哈希/对象/时间/质量不合格时不产生 verified。
- 原始遥测与任务事件记录为 MCAP，权威 JSONL 支持重建；裁判读取独立真值轨迹、任务结果与实际影像，离线重判必须与在线结果一致。证据缺失属于错误或不确定，不能自动算安全中止。

## 云端执行边界

复用现有 `scripts/dev_stack.py`，新增显式 M1 验证入口；只对 `drone-agent-cloud` 工作区操作。源码先提交为不可变 SHA，再部署验证。仿真期间保留本项目历史产物，其他容器身份前后比较；无新增宿主端口、系统配置、CI/CD、数据库迁移或全局安装。

## 验收记录要求

每个场景记录注入位置（传输/运行时输入/物理模型）、种子、随机化量、进程 PID、起止时间、软件 SHA、配置哈希、三分类结果、错误成功报告数及产物哈希。运行时注入电量/新鲜度不能冒充电池放电/真实传感器损坏；确定性适配器测试不能冒充 PX4 SITL。

未达到任一硬门槛时，路线图保持进行中，留下确切缺口与复现入口。只有同一候选 SHA 上的必要检查、云端任务闭环与故障矩阵全部通过后才关闭 M1。
